# Suprnova Live -- Iteration 006

Status: Scope contract
Agreed: 2026-09-08

## In

Iteration 006 is the sweep of everything iteration 005 staged rather than
built. Every capture under `iterations/next/` that was staged during
iterations 004 and 005, and the five candidates the RenderCache qualification
plan raised, is promoted into this contract and merged into its owning domain
specification. Nothing here opens a new subsystem; each item closes a gap
that an earlier review, ruling, or honest-boundary statement named and that
the current code either works around by hand or documents as a limit.

The delivery order is the controller's to decide inside this contract, but
the grouping below names the domains each item binds and the order in which
their risks compound: correctness and coherence first, so that every later
item builds on generations and classification that are exact; observability
and build shape second; the cross-language contract changes third; the two
design projects fourth, each with its design recorded in its domain
specification before code; and the manual parity work last, because it is
translation volume rather than design.

### Cache correctness and coherence

- Authorization decisions record the identity axis and the concrete identity
  they consulted, so a genuinely per-tenant gate caches under `Tenant` alone
  while a per-user or unresolved decision keeps requiring `Principal`
  (`16-cache-variance-privacy-and-stitching.md`).
- Eloquent global-scope evaluation observes the tenant it reads as
  comparable material, so a tenant-scoped scope on an undeclared route is
  declined instead of published (`16-cache-variance-privacy-and-stitching.md`).
- Feature-flag reads observe a `Feature` generation that a flag flip or an
  out-of-band reload advances, and the reload notifies the cached evaluator
  (`17-dependency-tracking-and-generations.md`).
- The RenderCache write side opens in every process that writes through the
  ORM, not only the serving process, so generation advances travel with the
  write (`16-cache-variance-privacy-and-stitching.md`,
  `17-dependency-tracking-and-generations.md`).
- Primary-key point reads observe the record they returned rather than the
  whole table, so a write to another row leaves the entry current
  (`17-dependency-tracking-and-generations.md`).
- A generation-ledger epoch rewind after a database restore is detected, and
  no entry stamped above the ledger's current authority is served
  (`18-cache-coherence-and-rebuilding.md`).

### Observability and build shape

- The `declined` lookup outcome carries a closed `reason` attribute, exhaustive
  over every decline branch at compile time
  (`16-cache-variance-privacy-and-stitching.md`).
- A documented production build shape turns the `testing` feature off; the
  framework, a scaffolded application, and the dogfood application build and
  boot in it, and the feature matrix covers it (`conventions.md`,
  `15-render-representations-and-storage.md`).
- `RenderCache::install` takes the application's build id, so the default
  build id changes with the application rather than with the framework crate
  (`15-render-representations-and-storage.md`).

### Contracts and negotiation

- The registered-event descriptor fields become `maximum_hops`,
  `maximum_fanout`, and `payload_contract` as one versioned descriptor change
  across the runtime, the reference host, the fixtures, the framework, and the
  browser host (`14-events-and-asynchronous-updates.md`).
- The `Media` and `Encoding` variance dimensions negotiate for real over a
  closed declared set, replacing the constants the middleware resolves them
  to today (`16-cache-variance-privacy-and-stitching.md`).

### Design projects

- Nested cached segments: a cached segment MAY contain cached segments, with
  an identity and version of its own, acyclic depth-bounded ownership, a
  composing privacy rule, per-request reauthorization, closed failure
  policies, one typed framework declaration, distinguishing telemetry, and a
  nested conformance case. The mechanism is chosen and recorded in
  `16-cache-variance-privacy-and-stitching.md` before code
  (`15-render-representations-and-storage.md` for the entry shape).
- Credible generation hints over Redis pub/sub: a hint MAY only shorten a
  validation lease a node already holds; hints are never authority; a
  deployment with hints lost or off behaves exactly as today. The bounds are
  settled in `18-cache-coherence-and-rebuilding.md` before code.

### Manual

- Inline-code-span parity holds across the whole manual: the six mirrors agree
  with English for every chapter, the rule's tokenizer reports only real
  drift, and the ratchet list is retired because every source is covered
  (`conventions.md`).

## Out

Out means sequenced build order, not removal from the agreed system.

- Specs 20 through 25 remain the official component-library iteration; this
  iteration does not implement the Tailwind component catalog, theme tokens,
  visual catalog, or theming studio.
- No browser substrate replaces the optional Stimulus integration; no SPA or
  Turbo-style navigation, Inertia mixing, virtual DOM, browser-rendered
  private shell, streamed trusted HTML, generic RPC protocol, or synthesized
  no-JavaScript action path is introduced.
- No application imports the internal engine crate, macro development crate,
  Askama parser, Redis client, SeaORM internals, or browser implementation
  modules merely to use Live or RenderCache.
- No file in `/home/shawn/workspace2/suprnova-magnetar` is modified.
- The standalone `suprnova-live` repository stays historical: it is not
  deleted, rewritten, or used as a second maintained branch.
- Dedicated-environment benchmark qualification stays release-checklist work;
  local results stay `exploratory` and the absence of S1 and B1 evidence stays
  recorded as absent.
- Any idea that surfaces while delivering this contract is captured under
  `iterations/next/` for iteration 007; it does not widen this contract.

## Definition of done

Iteration 006 is done only when all of the following are true:

1. `Gate::allows`, or its evaluation path, records the identity axis and the
   concrete identity a decision consulted. A decision that consults only a
   tenant-scoped fact classifies and key-compares as `Tenant` material; one
   that consults a per-user fact keeps requiring `Principal`; one that consults
   both axes, or that the recording cannot resolve, keeps the conservative
   behaviour. The privacy leak suite proves a per-tenant-only gate never
   leaks one tenant's page to another tenant sharing the key, and RBAC role
   and permission reads through `DB::select_one` and `DB::scalar` observe
   their tables precisely before such a route is stored.
2. Global-scope evaluation that reads a tenant records the tenant as
   comparable material. A route whose model carries a tenant-scoped global
   scope and declares no `Tenant` variance is declined, with a positive
   control proving the same route declaring `Tenant` caches and partitions. A
   scope that reads no per-request state records nothing; a per-request read
   the recording cannot resolve narrows to `Uncacheable`.
3. A flag flip through `set_flag`, or an out-of-band change reflected through
   `DatabaseEvaluator::reload()`, advances a `Feature` generation that an
   `is_enabled!` read of that flag observed, and a published entry that
   depended on the flag is invalidated through the coherence path.
   `reload()` notifies the cached evaluator. No `Feature` dependency is
   recorded for a flag with no scoped rule.
4. A write made by a queue worker, a scheduled task, or a console command
   advances the same generations the same write advances in the serving
   process, and `bump_permission_version` from such a process advances the
   persisted permission generation, each proven by a test that performs the
   write outside the served application and observes the next lookup
   rebuild. A process with RenderCache disabled opens nothing and writes
   nothing to the ledger. The honest-boundary bullet and the manual bullet
   that describe the old limit are removed.
5. A primary-key point read that returns a row observes that record's
   generation rather than the table's; one that returns no row, and every
   read whose row set is not fixed by a primary key, keeps the table
   observation. A write to another row of the same table leaves a point-read
   entry current; a write to the observed row, or its deletion, invalidates
   it. The invalidation-storm workload records the point-read ratio, and the
   generations chapter of the manual states the rule.
6. A restore that rewinds the generation ledger's epoch below the value live
   nodes or L1 entries carry is detected: no entry stamped above the ledger's
   current authority is served as current, proven by a test that performs a
   rewind and observes the refusal and the rebuild. The operations chapter's
   restore procedure states the automatic behaviour and keeps the manual
   steps only where they are still needed.
7. The `declined` lookup outcome carries a `reason` attribute whose values
   are a closed enumeration fixed at compile time with no request-derived
   text. Every branch that declines a store or a serve maps to exactly one
   reason, and adding a decline branch without a reason fails to compile. The
   session-value, per-principal-gate, and undeclared-locale declines are
   distinguishable from one another and from an ineligible response. The
   reason set is documented beside `outcome` in the operations chapter and its
   mirrors and asserted by the operations suite.
8. A documented production build shape exists in which the `testing` feature
   is off. The framework, the CLI scaffold's generated application, and the
   dogfood application build and boot in it. Every test seam is absent from a
   binary built that way, checked by a build assertion or a test rather than
   by reading. The default build and every `_for_test` consumer are
   unchanged, and the feature matrix step covers the testing-off build of the
   framework crate.
9. `RenderCache::install` takes the application's build id, or derives it in
   the application crate, so the default no longer equals the framework
   crate's version. A test proves two installs with different application
   build ids never share an entry, and the rustdoc and the deployment chapter
   name the source of the value.
10. The registered-event descriptor fields are `maximum_hops`,
    `maximum_fanout`, and `payload_contract`, shipped as one versioned
    descriptor change: runtime decoder, reference host, conformance fixtures
    with their manifest digests, framework issuance, and browser host change
    together, and the previous names are refused. Every public JSON field of
    the descriptor is `snake_case`, a generated contract mirrors the names
    into TypeScript, and the iteration 004 browser evidence is regenerated
    against the new descriptor under its existing unqualified label.
11. A route declaring `Media` or `Encoding` variance partitions its
    representations by the negotiated media type or content coding drawn
    from a closed declared set. The key, the `Vary` header, and the stored
    representation agree; a negotiation result outside the declared set falls
    back to the declared default rather than creating a variant. Tests prove
    two negotiations yield two representations and that a variant is never
    served to a request that did not negotiate it. The representations
    chapter replaces the constants statement.
12. Nested cached segments meet the promoted note's acceptance criteria in
    full: independent identity and version; acyclic, depth-bounded ownership
    declined at publication; assembled length known before any byte is
    copied; no inner segment served under a wider class or a longer freshness
    window than its includer; per-request reauthorization or proven identity
    freedom; failure resolved through `fail_document`, `omit`, or `fallback`;
    one typed framework declaration where drift fails the segment;
    distinguishing closed-label telemetry; a nested conformance case whose
    unknown depth or kind is rejected. The mechanism is recorded in the
    domain specification before the first code commit.
13. Credible generation hints over Redis pub/sub meet the promoted note's
    acceptance criteria in full: a hint only shortens a held lease and never
    extends, creates, or substitutes for the ledger; forged, duplicated,
    reordered, stale, or lost hints leave served output identical to hints
    disabled; publication and subscription are bounded and never block an
    unrelated request; the database and embedded tiers are unaffected; no new
    daemon is required. The bounds are recorded in the domain specification
    before the first code commit.
14. Inline-code-span parity holds across the whole manual: the rule's
    tokenizer treats quoted backticks so that only real drift is reported,
    every real drift is fixed by translation, the ratchet list in
    `check-manual-structure.py` is retired because every source is covered,
    and the translation lock is restamped for every chapter that changed.
15. Every promoted capture note is merged into its target domain
    specification with a dated decision entry, and its note is marked
    promoted. `node crates/suprnova-live/scripts/check-specs.mjs`, the
    integrated browser checks, the affected Rust checks, and Suprnova's normal
    gate all report their exact result; no placeholder, skipped command, or
    relabelled local measurement converts missing evidence into success.
