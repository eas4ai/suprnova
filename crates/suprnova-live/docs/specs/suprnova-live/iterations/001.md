## Definition of done

Iteration 001 is done only when all of the following are true:

1. The repository contains a documented Rust 2024 `suprnova-live` library
   workspace and strict TypeScript conformance package with exact lockfiles,
   license inventory, MSRV, supported feature declarations, and no dependency
   on the active Suprnova source tree.
2. The in-scope APIs are cohesive internal-ready contracts with typed errors,
   useful rustdoc, no production `unsafe`, no placeholder adapters, no
   `todo!()`, no `unimplemented!()`, and no panic path reachable from hostile
   input.
3. Canonical signed bytes follow the versioned RFC 8785-compatible JSON profile;
   HKDF-SHA-256 derives purpose/version keys; HMAC-SHA-256 signs them; key IDs,
   rotation overlap, bounded validity, and constant-time verification are
   implemented and tested.
4. Seed and instanced schemas bind every required component, build, route, slot,
   scope, revision, timing, and integrity dimension. Public seeds exclude
   principal-bound, tenant-private, secret, transient, and reusable instance
   state.
5. Promotion verifies the complete seed and trusted request scope, treats the
   at-least-128-bit browser nonce as untrusted identity input, atomically creates
   one independently scoped instance, and bounds rate, outstanding instances,
   and abandoned retention. Replay cannot join or replace another instance.
6. Tier 0 ledger tests prove atomic expected-revision claims, monotonic
   successors, duplicate outcome lookup, consumed-revision behavior, expiry,
   missing-ledger refresh, and at most one committed accepted outcome per base
   revision without claiming exactly-once method invocation or external effects.
7. Request and response envelopes have explicit versions, field and collection
   limits, duplicate/unknown handling, correlation, idempotency, compatibility,
   and safe recovery categories. Redirect precedence, morph-before-browser
   commit, explicit no-render, and post-acceptance refresh-without-replay are
   represented in shared conformance fixtures even though DOM execution belongs
   to iteration 003.
8. Rust and TypeScript consume the same golden success and failure fixtures for
   canonical bytes, signatures, snapshots, protocol envelopes, compatibility,
   and response ordering. Each side rejects fixtures the other rejects.
9. Negative tests cover field tampering, malformed canonical data, wrong key or
   purpose, expired and retired keys, cross-component/route/slot/scope
   substitution, nonce reuse, seed replay, storage exhaustion, stale revision,
   duplicate request, oversized/deep input, and redaction.
10. Property tests cover supported canonical round trips and schema evolution;
    fuzz targets cover every external parser and verifier without panics or
    unbounded allocation. Deterministic concurrency tests use barriers and
    injected clocks rather than sleeps.
11. The benchmark records complete environment metadata, labels unqualified
    hardware `local_exploratory`, and passes the `A8/16` 500-microsecond p95
    snapshot-processing cap with at least 30 measured post-warmup samples.
    Fixture assertions prove fixed request/response control overhead is at most
    1 KiB and snapshot framework overhead is at most 768 bytes for the named
    workload. A validated `S1` result remains mandatory before the first release
    or public performance claim; it is release qualification, not a blocker for
    completing this internal development iteration.
12. `scripts/gate.sh` runs unattended and includes, at minimum, the structural
    spec checker, format check, Clippy review without blanket `-D warnings`, all
    feature/target tests, doctests, Rust/TypeScript fixture parity, TypeScript
    format/lint/type/test/build checks, security tests, and the in-scope budget
    gate.
13. These exact commands pass from the repository root:

    ```bash
    node scripts/check-specs.mjs
    git diff --check
    CARGO_INCREMENTAL=0 cargo fmt --all --check
    CARGO_INCREMENTAL=0 cargo clippy --all-targets --all-features
    CARGO_INCREMENTAL=0 cargo test --all-targets --all-features --no-fail-fast
    CARGO_INCREMENTAL=0 cargo test --doc --all-features
    (cd browser && npm ci)
    (cd browser && npm run format:check)
    (cd browser && npm run lint)
    (cd browser && npm run typecheck)
    (cd browser && npm test)
    (cd browser && npm run build)
    (cd browser && npm run budget)
    CARGO_INCREMENTAL=0 scripts/gate.sh
    ```

14. Documentation explains each in-scope public/internal boundary, threat
    assumption, provider guarantee, failure outcome, fixture format, and budget
    reproduction command. The spec set, optional Fable handoff archive when
    present, examples, and generated artifacts are current.
15. No Suprnova or Magnetar file is modified, no migration is performed, and no
    iteration 002 through 007 capability is presented as implemented.
