# TypeScript 类型

`suprnova generate-types` 会扫描您的 Rust 源码，找出 `#[derive(InertiaProps)]` 和 `#[derive(Data)]` 结构体，并写出前端可以导入的 TypeScript 声明。在您改动 props 或路由之后运行它；除非您传了 `--skip-types`，`suprnova serve` 会在启动时替您运行它。

## 生成了什么

三个文件，写入到 `frontend/src/types/` 里：

| 文件 | 内容 |
|---|---|
| `inertia-props.ts` | 每个 prop 结构体对应一个 `export interface` - 总是会被写出 |
| `routes.ts` | 一个从 `src/routes.rs` 派生出来的 `controllers` 对象，以及 `routes` 具名查找映射表 - 只有带上 `--routes` 才会被写出 |
| `lang-keys.ts` | 一个 `MessageKey` 字符串字面量联合类型，涵盖默认语言区域目录里的每一个 Fluent 消息 id，包括其回退的父级目录 - 只有当 `lang/` 产出了任何 id 时才会被写出（参见[消息键](#消息键)） |

三个文件都以一条标注“自动生成”的头部注释开头。不要手工编辑它们 - 您的改动会在下一次运行时被覆盖掉。

## 运行它

```bash
# 一次性运行
suprnova generate-types

# 每次 Rust 文件变更时重新生成
suprnova generate-types --watch

# 为 props 文件自定义输出路径
suprnova generate-types --output frontend/src/types/props.ts
```

路由文件的路径固定在 `frontend/src/types/routes.ts`，消息键文件固定在 `frontend/src/types/lang-keys.ts`；只有 props 文件的路径是可配置的。这个监视器会监视 `src/`，在某个 `.rs` 文件被创建、被写入或者被删除时重新生成 props 文件；当项目里有一个 `lang/` 目录时，它也会监视那棵目录树，在某个 `.ftl` 文件发生同样这几类变更时重新生成 `lang-keys.ts`。读取不算数 - 这个生成器每跑一趟都会读遍 `src/` 底下的每一个 `.rs` 文件，要是把这也当成一次变更，这个监视器就会永远重新生成下去。一阵密集的保存会合并成一次运行，在最后一次写入之后 500 毫秒才跑，所以一次 `cargo fmt` 或者一次分支切换只会重新生成一次，而且是照着改完之后的目录树生成的，而不是每个文件生成一次、还是照着一棵改到一半的目录树。

每一趟只在发出的内容与已经在那里的内容不同时才写文件。一次什么都没有改变的重新生成会报告 `<path> is up to date`，并且原封不动地留下这个文件以及它的时间戳 - 正是这一点，让 `suprnova serve` 不会因为一个它决定不写的文件而重启您的后端。

## 页面 props

预期的形态是：每个 Inertia 页面对应一个 Rust 结构体，派生 `InertiaProps`，并与一个页面组件配对，这个页面组件的 props 类型取自生成出来的这个接口。

```rust
// src/controllers/home.rs
use suprnova::{InertiaProps, Request, Response, inertia_response};

#[derive(InertiaProps)]
pub struct HomeProps {
    pub title: String,
    pub message: String,
    pub count: i64,
    pub tags: Vec<String>,
    pub avatar_url: Option<String>,
}

pub async fn index(req: Request) -> Response {
    inertia_response!(&req, "Home", HomeProps {
        title: "Welcome".into(),
        message: "Hello".into(),
        count: 3,
        tags: vec!["new".into(), "featured".into()],
        avatar_url: None,
    })
}
```

`suprnova generate-types` 会产出：

```typescript
// frontend/src/types/inertia-props.ts
// This file is auto-generated by Suprnova. Do not edit manually.
// Run `suprnova generate-types` to regenerate.

export interface HomeProps {
  title: string;
  message: string;
  count: number;
  tags: Array<string>;
  avatar_url: string | null;
}
```

不管前端框架是什么，消费它的方式都一样 - 这行 `import type` 在 Svelte、React 和 Vue 之间是完全一致的：

```svelte
<!-- frontend/src/pages/Home.svelte（默认脚手架） -->
<script lang="ts">
  import type { HomeProps } from '../types/inertia-props'

  let { title, message, count, tags, avatar_url }: HomeProps = $props()
</script>

<h1>{title}</h1>
<p>{message} - {count} items</p>
{#if avatar_url}<img src={avatar_url} alt="" />{/if}
```

关于 React 和 Vue 的对应写法，请参见[页面组件](frontend-pages.md)。

## 类型映射

| Rust | TypeScript | 说明 |
|---|---|---|
| `String`、`&str` | `string` | |
| `i8`..`i128`、`u8`..`u128`、`isize`、`usize`、`f32`、`f64` | `number` | 所有数值原生类型都收敛成 `number` |
| `bool` | `boolean` | |
| `Option<T>` | `T \| null` | |
| `Vec<T>` | `Array<T>` | props 生成器发出的是 `Array<T>`；routes 生成器对表单请求字段发出的是 `T[]` |
| `HashMap<K, V>`、`BTreeMap<K, V>` | `Record<K, V>` | |
| `serde_json::Value` | `JsonValue` | 一个递归的别名，生成器只在文件顶部声明它一次，而且只在确实有东西引用它的时候才声明。裸写的 `Value` 也映射到这里，除非项目自己定义了一个 `Value` 结构体 - 那种情况下以项目自己的为准 |
| `Field<T>`（来自 `#[derive(Data)]`） | `field?: T \| null` | Field 在传输中是可选的 |
| `Prop<T>`（lazy / deferred） | `field?: T` | Lazy props 省去了 `null` 那一半 |
| 其它任何东西 | 裸标识符 | 见下面的“自定义类型” |

## 自定义类型

这个访问器能识别上表里列出的这些原始类型。其它任何东西都会以它裸露的 Rust 类型名发出。这带来两个后果：

**一个嵌套的结构体，只有在它派生了 `InertiaProps` 或者 `Data` 时，才会拿到自己的接口。** 一个裸的 `#[derive(Serialize)]` 结构体，对这个生成器是不可见的 - 发出的这个接口会按名字引用它，但不会产出任何声明：

```rust
use serde::Serialize;
use suprnova::{Data, InertiaProps};

#[derive(Serialize)]
pub struct Address {  // 不会被识别到 - 没有 InertiaProps/Data 派生
    pub street: String,
    pub city: String,
}

#[derive(Data)]      // 或者 InertiaProps - 两者都行
pub struct Company {
    pub name: String,
    pub address: Address,
}

#[derive(InertiaProps)]
pub struct ProfileProps {
    pub user_name: String,
    pub company: Company,
}
```

生成出来的输出：

```typescript
export interface Company {
  name: string;
  address: Address;          // 悬空 - 没有发出 Address 接口
}

export interface ProfileProps {
  user_name: string;
  company: Company;
}
```

修复方法：给 `Address` 加上 `#[derive(Data)]`（或者 `InertiaProps`）。运行时的序列化行为不受嵌套结构体上这个派生选择的影响 - `serde_json` 仍然会正确地发出这个结构体 - 但 TypeScript 需要这份显式的声明。

**自定义类型上的泛型参数不会被递归处理。** `chrono::DateTime<Utc>`、`uuid::Uuid`、`rust_decimal::Decimal`，以及您自己那些没有派生的类型，都会以裸露的最前面那个标识符发出（`DateTime`、`Uuid`、`Decimal`）。它们在传输中会序列化成 JSON 字符串，但这个 TypeScript 声明不会说明这一点。有两种办法能处理这件事：

```typescript
// frontend/src/types/runtime-types.ts - 手写的，与生成出来的文件放在一起
export type DateTime = string;        // chrono::DateTime<_> 序列化为 RFC 3339
export type Uuid = string;
export type Decimal = string;         // serde_with 的默认值；rust_decimal::Decimal
```

然后在 `tsconfig.json` 里，确保它们会通过您的 `include` glob 被纳入，或者在需要的地方写 `import type { DateTime } from './runtime-types'`。框架不会替您发布这些别名，因为正确的选择（`string` 还是 `number` 还是带品牌的类型）取决于您启用了哪些 serde feature flag。

## 泛型结构体

一个泛型 Rust 结构体，会变成一个泛型 TypeScript 接口：

```rust
use suprnova::{Data, data::Field};

#[derive(Data)]
pub struct Paginated<T>
where
    T: serde::Serialize + for<'de> serde::Deserialize<'de>,
{
    pub items: Vec<T>,
    pub total: usize,
    pub cursor: Field<String>,
}
```

```typescript
export interface Paginated<T> {
  items: Array<T>;
  total: number;
  cursor?: string | null;
}
```

这个 `where` 子句会被丢弃 - TypeScript 的泛型是不受约束的，除非您在消费方另外指明。

## 拆分输入 / 输出接口

当一个 `#[derive(Data)]` 结构体混用了 `#[data(input_only)]`、`#[data(output_only)]` 或者 `#[data(lazy)]` 字段时，会发出两个接口 - 输出的那个形态（前端收到的东西），以及一个 `<Name>Input` 的对应物（它送回去的东西）：

```rust
use suprnova::Data;
use suprnova::data::Field;
use suprnova::inertia::Prop;
use validator::Validate;

#[derive(Data, Validate)]
pub struct UserDto {
    pub id: i64,
    pub name: String,

    #[data(input_only)]
    #[validate(length(min = 8))]
    pub password: String,

    #[data(output_only)]
    pub computed_handle: String,

    pub bio: Field<String>,

    #[data(lazy)]
    pub favorite_song: Prop<String>,
}
```

两者都会发出：

```typescript
export interface UserDto {              // 服务器 -> 客户端
  id: number;
  name: string;
  computed_handle: string;
  bio?: string | null;
  favorite_song?: string;
}

export interface UserDtoInput {         // 客户端 -> 服务器
  id: number;
  name: string;
  password: string;
  bio?: string | null;
}
```

`Prop` 字段天生就是仅输出的，所以即便 `lazy` 没有被显式标注，它们也会从输入类型里被剔除。关于完整的一套 `#[data(...)]` 标志及其编写语义，请参见[数据对象](data.md)。

## 类型安全的路由

带上 `--routes` 之后，这个命令会写出第二个文件，`frontend/src/types/routes.ts`，由 `src/routes.rs` 生成而来。它暴露出一个 `controllers` 对象，它的方法形态镜照您后端的模块树，再加上一个按 `.name(...)` 加键的 `routes` 查找表：

```rust
// src/routes.rs
use suprnova::routes;

routes! {
    get!("/", controllers::home::index).name("home"),
    get!("/users", controllers::user::index).name("users.index"),
    get!("/users/{id}", controllers::user::show).name("users.show"),
    post!("/users", controllers::user::store).name("users.store"),
}
```

```typescript
// frontend/src/types/routes.ts
import type { Method } from '@inertiajs/core';

export interface RouteConfig<TData = void> {
  url: string;
  method: Method;
  data?: TData;
}

export interface UserShowParams {
  id: string;
}

export const controllers = {
  home: {
    index: (): RouteConfig => ({ url: '/', method: 'get' }),
  },
  user: {
    index: (): RouteConfig => ({ url: '/users', method: 'get' }),
    show: (params: UserShowParams): RouteConfig =>
      ({ url: `/users/${params.id}`, method: 'get' }),
    store: (): RouteConfig => ({ url: '/users', method: 'post' }),
  },
} as const;

export const routes = {
  'home': controllers.home.index,
  'users.index': controllers.user.index,
  'users.show': controllers.user.show,
  'users.store': controllers.user.store,
} as const;
```

`RouteConfig` 特意被塑造成满足 Inertia 3 的 `UrlMethodPair` 接口的形态，所以它能直接插进 `router.visit`、`useForm` 的 `submit`，以及 `<Link href={...}>`，不需要任何适配器：

```ts
import { router } from '@inertiajs/svelte'   // 或者 /react 或 /vue
import { controllers, routes } from '../types/routes'

router.visit(controllers.home.index())
router.visit(controllers.user.show({ id: '42' }))
router.visit(routes['users.show']({ id: '42' }))
```

如果一个路径带有参数（`/users/{id}`），生成出来的这个函数就需要那个类型化的 `Params` 对象 - TypeScript 会在编译期抓住缺失或者拼错的键。

## 消息键

如果应用有一棵 `lang/` 目录树，这个生成器还会写出 `frontend/src/types/lang-keys.ts`：一个 `MessageKey` 字符串字面量联合类型，涵盖前端能解析出来的每一个 Fluent 消息 id。起步套件的 `t()` 包装函数把它的键参数类型标注为 `MessageKey`，所以一个打错或者被删掉的键，会成为一个指向该组件的 TypeScript 错误 - 这正是 `inertia-props.ts` 对 props 做出的那份承诺，延伸到了翻译上。

这些 id 来自 `lang/<APP_LOCALE>/*.ftl`，并会与这个语言区域已配置的那些回退父级（`APP_LOCALE_PARENTS`）做联合 - 所以一个只保留了它所覆盖的那些字符串的、delta 风格的目录，仍然会生成出那份完整的键集，与实际提供服务的、经过链式扁平化的目录所携带的键集一致。`APP_FALLBACK_LOCALE` 是故意*没有*被包括进来的：实际提供服务的目录同样不会去扁平化这个终端兜底，而这个联合类型必须精确描述浏览器拿到的那一份目录能解析出什么。关于这条链本身，请参见[本地化](localization.md)。

这个文件遵循和另外两个一样的规则：固定路径、自动生成的头部注释、确定性的排序输出、永不手工编辑。当没有任何 `.ftl` 文件产出任何 id 时，这个文件会被删除，而不是被发出成一个空文件 - 一个导入了 `MessageKey` 的套件，就会编译失败，直到这份目录重新有了 id 为止，这和这条管线里的其它每一次漂移一样醒目。

## 什么时候运行

`suprnova serve` 会在启动时触发 `generate-types`。默认的流程：

```
suprnova serve
  ├─ 扫描 src/ 里的 InertiaProps / Data 结构体          → inertia-props.ts
  ├─ 扫描 src/routes.rs 里的路由定义                    → routes.ts
  ├─ 扫描 lang/ 里的 Fluent 消息 id                     → lang-keys.ts
  ├─ 启动后端
  └─ 启动 Vite
```

传入 `--skip-types` 可以同时跳过两者。当后端在热重载、而您想要拿到新鲜的声明又不想重启服务器时，任何时候改动了 Rust 代码，都可以手动重新运行 `suprnova generate-types`。

### 提交这份输出，并预期一份干净的 diff

`inertia-props.ts` 是打算被纳入版本控制的 - 这正是让一位审阅者能在同一份 diff 里，看到 prop 契约的变化和引发它的那部分 Rust 代码放在一起的原因，也是让 CI 不需要一套 Rust 工具链就能对前端做类型检查的原因。

生成是确定性的：同一份源码，在任何机器上，不管文件恰好以什么顺序落在磁盘上，都会产出逐字节相同的输出。所以一次什么都没改变的运行，不会显示任何 diff，而您看到的任何 diff，都是一次真实的契约变化。（曾经并非如此 - 排序曾经从哈希的迭代顺序里取种子，每一次运行都会把这些接口重新洗一遍牌。）

两个值得记在心里的后果：

- **没有别的什么东西可以编辑这个文件。** 如果一个组件导入了一个这个生成器没有发出的类型，下一次 `generate-types` 就会把它删掉，前端也就没法编译了。修复方法是在 Rust 里声明这个类型，而不是手工编辑这份输出。
- **一个没有 Rust 路由的页面，没有生成出来的类型**，因为它背后没有一个 `#[derive(InertiaProps)]` 结构体。在有处理程序来拥有这些 props 之前，请在组件里本地声明它的 props。

## 为什么 Suprnova 有所不同

Laravel 没有为 Inertia 提供类型生成，因为 PHP 是动态类型的 - 服务器那一侧没有什么契约可以拿来提取。Inertia 的 Laravel 社区用用户态的工具（Laravel Typed Inertia、Wayfinder）填上了这个空缺，这些工具读取的是 PHPDoc 或者 DocBlock 注解。

Suprnova 在编译期、以及在磁盘上，就已经拥有这份类型信息，所以我们直接提取它。同一个控制着 JSON 序列化的 `#[derive(InertiaProps)]` 或者 `#[derive(Data)]`，也驱动着这份 TypeScript 输出 - 单一的真实来源，永远不会和 serde 实际发出的东西失去同步。
