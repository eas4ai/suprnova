# The form family renders no value from island state, so edit forms show empty controls, group selections vanish on re-render, and the checkbox group never saves

Surfaced from: FORM-001
Captured: 2026-09-17T11:53:47.515Z

Found 2026-09-17 in the adversarial review of Live and the component library before 2.1.0. The input, textarea, number-input, slider, search-input, checkbox, radio-group, switch, select, combobox and date-picker macros take no value, checked or selected parameter and render none. The runtime never writes island state into controls: crates/suprnova-live/browser/src/continuity/forms.ts only restores a value the user changed, measured against the server-rendered default, and models/forms.ts prepareAction proposes every control of the submitted form. Reproduced against the dogfood host on /live/forms: the Seats input renders empty although FormGallery mounts quantity = 1; an untouched Save proposes bio "", country "", newsletter false, quantity null and volume 50; after the reset action every control still shows what was typed; a checked plan radio is cleared by the next re-render, because group inputs carry no id and fall outside continuity; and the checkbox group proposes a boolean (models/control.ts reads each checkbox as checked), never a list, so topics stays empty. An edit form built from these macros overwrites stored text and boolean fields with empty values.
