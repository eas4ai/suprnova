# Suprnova Live -- Iteration 004

Status: Scope contract
Agreed: 2026-08-23
Amended: 2026-08-24 -- carried the corrected optional Stimulus delivery boundary

## In

Iteration 004 is the complete standalone upload and asynchronous-update
foundation. It implements specifications 08 and 14 in full: temporary upload
identity, reverse-proxy/file transfer, provider-neutral direct storage,
quarantine and validation, finalization and cleanup, upload browser behavior,
typed component/browser events, authorized SSE and WebSocket delivery, bounded
polling, continuity-aware reconnect, and push-triggered refresh or
presentation-only updates.

The implementation remains inside this dedicated development workspace and
continues to target the eventual internal Suprnova crate. Host-neutral traits,
reference providers, production-mode browser artifacts, shared fixtures, and a
reference HTTP/SSE/WebSocket host prove the contracts without claiming that the
active Suprnova checkout registers its router, storage, broadcasting, public
facade, or CLI integration. No source or path dependency on Suprnova or Magnetar
is introduced.

### Shared bounded-resource foundation

- Add document-owned upload and asynchronous-update managers that reuse common
  lifecycle, cancellation, bounded queue, backpressure, diagnostics,
  observability, and browser-page-state primitives while retaining distinct
  upload and event protocols.
- Associate every upload, poll, stream, timer, transport, and pending
  authoritative refresh with one validated document, island, directive, and
  stable DOM identity. Authoritative work enters only that island's existing
  scheduler.
- Bound per-document, per-island, and per-origin concurrency, queue items,
  buffered bytes, timers, retries, diagnostic retention, and shutdown work.
  Removal, replacement, navigation, freeze, bfcache restoration, and document
  retirement dispose or reconnect resources exactly once.
- Keep the foundation payload-neutral. It cannot dispatch arbitrary methods,
  evaluate JavaScript, install HTML, write snapshots, or create component/domain
  authority.
- Keep the universal core ESM/classic runtime within its existing 45 KiB Brotli
  cap. Compile the existing Stimulus bridge plus upload and asynchronous
  behavior as separate optional ESM/classic feature artifacts over one checked
  core lifecycle-driver attachment; trusted server-rendered requirements and the
  typed asset manifest select roles, never arbitrary element-provided URLs or
  modules. Stimulus remains application-supplied and is neither imported nor
  bundled by its adapter.

### Upload identity, protocol, and state

- [`08-file-uploads.md`](../08-file-uploads.md) -> implement a revisioned
  temporary-upload state machine with `created`, `queued`, `transferring`,
  `verifying`, `ready`, `finalizing`, and `finalized` progress plus explicit
  `rejected`, `canceled`, `expired`, and `failed` terminal dispositions.
- Perform each authoritative transition conditionally against the expected
  upload revision. Duplicate chunks, completion, cancellation, status, and
  finalization return an idempotent existing result or a typed conflict; state
  never moves backward.
- Represent temporary component/application state with an opaque bounded upload
  handle. The handle grants no authority, is expiring and unguessable, and is
  scoped and reauthorized for principal/session, tenant, component, field, and
  upload policy whenever it is used.
- Issue a separate short-lived transfer grant authorizing only bounded control
  and data-plane operations for one upload. The grant never enters a signed
  snapshot, rendered HTML, URL, browser history, log, trace, diagnostic,
  inspection output, or action/model envelope.
- Version upload control and data-plane messages independently from the Live
  action/morph protocol. Codecs reject unknown major versions, duplicate or
  unbounded fields, unsupported operations, invalid transitions, and authority
  mismatches before provider work.

### Transfer providers, validation, and finalization

- Implement the reverse-proxy/file transport as the standalone reference
  provider. It streams bounded chunks into quarantined temporary files without
  buffering an entire file in browser or server memory and requires no object
  storage daemon.
- Define provider-neutral direct-to-storage capabilities and conformance for
  constrained transfer instructions, part/chunk reporting, integrity evidence,
  completion, cancellation, expiry, cleanup, and authoritative verification.
  Provider mode cannot change handle authority or lifecycle semantics.
- Enforce server-side count, per-file size, aggregate size, chunk size,
  in-flight chunk, document/island concurrency, creation rate, temporary-storage,
  verification-time, retry, and retention limits. Browser `accept`, MIME,
  extension, filename, size, checksum, media metadata, and completion claims
  remain untrusted hints.
- Keep temporary content quarantined and non-public. Provide bounded integrity,
  content/type, name normalization, metadata, and application-policy validation
  plus asynchronous scanning hooks with timeout, unavailable, rejection, and
  retry policy. Rejected or unverified bytes cannot be finalized or served.
- Finalize only through a deliberate authorized application action that
  reauthorizes the ready handle and application scope. The provider contract
  exposes preparation, durable commit, idempotent existing outcome,
  compensation, retry, and reconciliation instead of pretending storage and the
  application database share one transaction.
- Make cancel, remove, expiry, and cleanup race-safe against transfer,
  verification, and finalization. Cleanup is idempotent, observable, and able to
  reclaim abandoned bytes without a browser callback.

### Upload browser behavior

- Promote `live:upload` and `live:progress` into the closed directive grammar.
  `live:upload` owns one declared upload field and registered cancel, retry, and
  remove roles; `live:progress` exposes scoped truthful status. Values are
  registered names or typed bounded literals, not endpoints, grants, paths, or
  executable expressions.
- Use native file inputs as the only browser file-selection authority. The
  runtime never restores a path, writes a native file value, invents a `File`,
  or serializes bytes into Live JSON/snapshots. Immediate browser-known checks
  cannot claim authoritative server validation.
- Queue chunks under declared scheduling and backpressure while unrelated
  island work remains available. Progress distinguishes queued, transferring,
  verifying, ready, finalizing, finalized, interrupted, failed, canceled, and
  expired state where applicable and never claims success before authoritative
  verification.
- Guarantee retry/resume only within the current document/connection lifecycle.
  No default `localStorage`, `sessionStorage`, or IndexedDB persistence is
  introduced. An application may explicitly reacquire a handle and new grant
  through an ordinary authenticated route after reload; otherwise expiry and
  cleanup own recovery.
- Preserve active uploads across compatible keyed morphs without transferring a
  browser file to unrelated identity. Replacement/removal communicates
  cancellation or required reselection, and navigation may provide an
  accessible leave/stay guard without trapping the user or claiming rollback.
- Make progress and cancel/retry/remove controls semantic, keyboard operable,
  focus-safe, and screen-reader usable. Throttle progress announcements to avoid
  live-region noise and honor reduced-motion behavior.

### Typed events and subscriptions

- [`14-events-and-asynchronous-updates.md`](../14-events-and-asynchronous-updates.md)
  -> complete registered typed component and browser events with generated name,
  payload schema, source, target, propagation scope, ordering, cycle, fanout,
  and lifecycle metadata.
- Support checked self, parent, child, named-island, document, and approved
  browser-listener scopes without making a global arbitrary event bus. Unknown,
  malformed, cyclic, over-fanout, or retired-target delivery cannot invoke
  unregistered behavior.
- Render a signed, expiring, bounded subscription descriptor containing only
  registered stream identity, protocol/capability metadata, topic scope, typed
  events, authorization memo, authoritative baseline epoch/sequence, and
  reconnect policy. Endpoints and topics cannot come from unchecked directive
  interpolation.
- Treat subscription tokens or transport credentials as non-loggable secrets.
  Establishment and renewal reauthenticate and authorize principal, tenant,
  component, stream, and topic; removal and navigation unsubscribe.

### SSE, WebSocket, polling, and continuity

- Implement authorized SSE and WebSocket transports over one independently
  versioned typed event-envelope schema. Messages carry bounded stream,
  subscription, event type/schema, sequence, payload, and continuity metadata;
  they never carry trusted HTML, snapshots, DOM fragments, arbitrary action
  names, executable effects, or code.
- Permit push only to queue a registered authoritative refresh, dispatch a
  registered typed browser event, or update a declared presentation-only local
  signal. Push never automatically invokes a mutating Live action. Domain
  mutation occurs through normal authenticated server/application paths and may
  publish an invalidation afterward.
- Route every authoritative refresh through the existing island scheduler,
  protocol verification, rendering, commit-after-morph ordering, and recovery.
  Burst invalidations coalesce without losing required state changes or
  bypassing current authorization.
- Promote `live:stream` and `live:poll` into the closed directive grammar.
  Support explicit polling-only, push-only, and hybrid freshness policy with
  bounded interval, jitter, visibility, offline, immediate, coalescing, and
  retirement behavior.
- In the default hybrid policy, authorized push is primary and polling pauses
  only while sequence continuity is proved. Gaps, heartbeat loss, reconnect
  uncertainty, authorization failure, or replay exhaustion mark material state
  degraded and activate bounded jittered polling fallback.
- Maintain `disconnected`, `connecting`, `current`, `degraded`, `reconnecting`,
  and `closed` stream state. The signed server baseline binds initial SSR state
  to the first required epoch/sequence. Ignore duplicates; never apply across a
  sequence gap; claim current status after initial connect or reconnect only
  when trusted replay proves continuity or an authoritative refresh establishes
  a new baseline.
- Bound connection count, subscriptions, event size, payload size, heartbeat,
  replay window, fanout, server and browser buffers, reconnect attempts,
  fallback polls, and delivery work. Slow consumers are safely coalesced,
  degraded, or disconnected instead of accumulating unbounded memory.
- Keep ordinary Live actions, HTTP routes/forms, and navigation working while
  push is absent or degraded. Expose connection/freshness state accessibly only
  when it materially affects the feature.

## Definition of done

Iteration 004 is done only when all of the following are true:

1. Upload and asynchronous-update modules use one bounded-resource foundation
   for lifecycle, cancellation, queueing, backpressure, diagnostics, and page
   ownership without exposing a generic RPC, arbitrary dispatch, HTML install,
   or authority-writing API. Document and island retirement dispose every owned
   task, timer, listener, connection, buffer, and permit exactly once.
2. Temporary upload identity separates an opaque typed handle from its
   short-lived transfer grant. Handle scope and expiry are reauthorized at each
   control/finalization boundary; handle possession alone grants nothing. Grant
   sentinel tests prove no secret reaches snapshots, HTML, URLs, history,
   action/model envelopes, logs, traces, diagnostics, or inspection output.
3. The upload state machine implements every declared progress and terminal
   state with monotonic revisioned conditional transitions. Duplicate, stale,
   concurrent, and reordered create/chunk/status/complete/cancel/finalize calls
   produce idempotent existing outcomes or typed conflicts and never regress
   state or duplicate durable work.
4. The independently versioned bounded upload control/data codecs reject unknown
   majors, oversized or duplicate fields, unsupported operations, invalid
   transition shapes, cross-upload reuse, and malformed values before expensive
   allocation, provider I/O, or state change. Property and fuzz suites cover
   round trips and hostile input.
5. The reverse-proxy/file provider streams actual HTTP chunks into quarantined
   temporary storage with bounded server/browser memory, descriptor use,
   concurrency, time, retry, and body size. It works without an external object
   storage daemon and survives controlled interruption, short writes, duplicate
   chunks, checksum failure, process shutdown, and disk/provider faults.
6. The provider-neutral direct-storage interface and reference conformance
   adapter prove constrained transfer instructions, part/chunk identity,
   integrity evidence, completion, verification, cancellation, expiry, and
   cleanup while preserving the same handle authority and state machine as the
   reverse-proxy/file provider. No concrete vendor adapter is falsely claimed.
7. Server enforcement covers declared and absolute count, file, aggregate,
   chunk, in-flight, concurrency, creation-rate, storage, validation, scanning,
   retry, age, and cleanup limits. Exhaustion tests fail one bounded scope
   safely, keep unrelated islands/routes usable, and expose no untrusted paths,
   bytes, or high-cardinality labels.
8. Authoritative validation reads quarantined bytes and safely handles filename,
   MIME/type, extension, size, integrity, application rules, bounded image/media
   metadata, and optional scanning. Timeout/unavailable/reject policy is
   explicit; unverified, quarantined, rejected, canceled, expired, or failed
   content cannot be finalized or served.
9. Finalization occurs only through a deliberate authorized action, rechecks
   principal/session, tenant, component, field, policy, revision, and readiness,
   and produces one durable logical outcome. Deterministic provider/database
   failure tests prove preparation, commit, idempotent retry, compensation, and
   reconciliation without claiming distributed atomicity or exactly-once
   external side effects.
10. Cancel, remove, expiry, and cleanup are race-safe against transfer,
    verification, scanning, and finalization. Cleanup is idempotent and bounded,
    reclaims abandoned content without browser cooperation, and reports safe
    age/volume/outcome/retry/orphan metrics.
11. `live:upload` uses native single/multiple file selection, creates no eager
    snapshot bytes or browser-trusted metadata, enqueues bounded transfers, and
    supports registered cancel/retry/remove roles. Multiple fields, replacement
    policy, repeated selection, directory/path oddities, zero-byte files,
    offline state, and unrelated island work have deterministic browser tests.
12. `live:progress` exposes truthful scoped queued/transferring/verifying/ready/
    finalizing/finalized/interrupted/failed/canceled/expired status and bounded
    numeric progress without premature completion. Keyboard, accessible name,
    focus, live-region throttling, reduced motion, and error association pass
    browser and accessibility fixtures.
13. Compatible keyed morphs preserve only the correct active file input,
    transfer, progress root, and controls. Removal, replacement, rekeying,
    navigation, and bfcache behavior communicate cancellation or reselection,
    never assign a file/path, never transfer ownership across islands, and
    dispose resources once.
14. Current-document interruption and resume retain one handle, grant, file,
    chunk map, and idempotency identity only for their permitted lifetime.
    Reload/restart introduces no ambient persistence; an explicit authenticated
    reacquisition fixture can issue a new grant, while absent/denied/expired
    reacquisition leads to safe cleanup.
15. Typed component/browser event metadata and dispatch cover registered name,
    schema, source, target, scope, order, cycle, fanout, and lifecycle. Self,
    parent, child, named-island, document, and approved browser listener tests
    prove exact ownership; malformed or retired targets cannot invoke arbitrary
    Rust or JavaScript behavior.
16. Signed subscription descriptors bind stream identity, protocol/capability,
    topics, typed events, authorization context memo, authoritative baseline
    epoch/sequence, expiry, and reconnect policy. Directive interpolation cannot
    choose an endpoint/topic; tokens and credentials are separately scoped/
    redacted; connection and renewal reauthorize principal, tenant, component,
    stream, and topic.
17. Authorized SSE and WebSocket implementations consume the same versioned
    bounded event-envelope semantics and pass transport-neutral conformance for
    sequences, duplicates, gaps, completion, errors, heartbeat, cancellation,
    authorization loss, payload limits, and shutdown. Unknown major versions
    fail closed without disconnecting ordinary HTTP Live behavior.
18. Push can only queue a registered refresh, dispatch a registered typed
    browser event, or update a declared presentation-only signal. Hostile and
    conformance tests prove it cannot invoke a mutating action, select arbitrary
    methods/effects, install HTML/snapshots/fragments, or write component,
    authorization, revision, or domain state.
19. Push-triggered refresh enters the existing island scheduler, coalesces
    bounded bursts, reauthorizes protected rendering, and applies only through
    normal response validation, morph preflight, commit-after-morph ordering,
    and fresh-render recovery. It introduces no second HTML or snapshot
    protocol.
20. `live:poll` supports explicit bounded interval, jitter, immediate/initial,
    visibility, offline, overlap, scheduler, stale-status, cancellation, and
    retirement semantics. Polling-only mode remains complete; hidden/offline/
    failed documents back off without synchronized storms or unsafe overlap.
21. `live:stream` supports explicit push-only and hybrid freshness policies.
    Hybrid mode pauses polling only under proved continuity and activates bounded
    jittered polling after a gap, heartbeat loss, replay failure, authorization
    uncertainty, or disconnect. Push-only mode exposes degraded state rather
    than silently inventing fallback.
22. Stream state and sequence handling distinguish disconnected, connecting,
    current, degraded, reconnecting, and closed. The server baseline proves the
    first required epoch/sequence; duplicates are ignored, gaps pause
    application, and initial connect or reconnect claims currentness only after
    trusted replay proof or authoritative refresh. Late/old delivery cannot
    overwrite a newer baseline or retired island.
23. Connection, subscription, message, payload, heartbeat, replay, fanout,
    server/browser buffer, reconnect, poll, and dispatch bounds pass slow-client,
    burst, global-outage, and multi-island tests. Backpressure coalesces, degrades,
    or closes according to typed semantics and never grows memory without bound.
24. Pagehide, freeze, resume, pageshow, bfcache, navigation, morph replacement,

    no duplicated listeners/connections/timers, no late response application,
    and safe reauthorization/reconnect after restoration.
25. Material upload and stream states integrate with existing feedback and local
