# Suprnova Live -- Iteration 002

Status: Scope contract
Agreed: 2026-08-21

## In

Iteration 002 is the complete standalone server-component kernel. It turns the
trusted interaction spine from iteration 001 into a usable host-neutral Rust
execution system for Askama views, typed Live components, lifecycle, state,
actions, validation, rendering, and endpoint response intent. It remains an
internal Suprnova subsystem under development, not a third-party crate, public
release, browser runtime, or claim of framework integration.

This confirmed contract supersedes the preliminary iteration-002 sequencing in
[`001.md`](001.md) only where that older schedule assigned actual Suprnova
router, HTTP, session, CSRF, authentication, authorization, tenant, macro-facade,
or CLI integration. Those adapters require edits and integration tests in the
active framework and therefore remain reserved for the atomic move of code,
normative specs, and checker into Suprnova. Kernel behavior and adapter
contracts are implemented here without a source or path dependency on the
active Suprnova or Magnetar checkouts.

### Views and initial rendering

- [`01-views-and-documents.md`](../01-views-and-documents.md) -> implement the
  host-neutral Suprnova view contract with Askama as the normative checked
  external-template substrate; safe escaping and explicit trusted markup;
  typed render inputs and document/island output metadata; deterministic
  failures; and bounded initial island emission using iteration-001 snapshots.
- Render results carry typed status, headers, content type, assets, mount
  metadata, and diagnostics as response intent. They do not import or imitate
  Suprnova `Request`, `Response`, or router types.
- A canonical document conformance adapter proves complete HTML, initial-content
  exposure, HEAD intent, conditional intent, mount boundaries, and failure
  behavior without claiming an actual registered Suprnova route.

### Components, lifecycle, and composition

- [`02-component-lifecycle-and-composition.md`](../02-component-lifecycle-and-composition.md)
  -> implement generated stable component metadata, explicit registration,
  duplicate/conflict detection, mount, verified hydration, model application,
  action/validation phases, render, deterministic dehydration, teardown, and
  phase-specific failure behavior.
- Implement typed mount and child parameters, developer-supplied stable keys,
  independent nested-island ownership, circular-composition bounds, removal,
  conditional components, and the server execution contract for lazy
  completion.
- Produce and verify signed child-parameter envelopes bound to the issuing
  parent instance and accepted revision, child key and component contract,
  parameter schema, and value hash. Browser scheduling and DOM preservation are
  deliberately absent.

### State and binding

- [`03-component-state-and-binding.md`](../03-component-state-and-binding.md)
  -> implement generated field metadata and runtime enforcement for ordinary,
  model-bindable, locked, transient, server-only, session-backed, and computed
  state categories.
- Apply bounded model proposals through registered typed codecs while
  preserving missing, null, invalid, and valid distinctions. Unknown or
  forbidden paths fail before action execution.
- Transient values remain request-only and absent from snapshots, rendered
  value attributes, diagnostics, events, effects, and host-adapter records.
- Check and emit binding timing and URL metadata. The host-neutral harness may
  supply typed initial query values and assert reflected-versus-navigated URL
  intent; browser event timing, debounce queues, `history.replaceState`, and
  document navigation execution remain iteration 003.

### Actions, validation, and accepted outcomes

- [`04-actions-and-validation.md`](../04-actions-and-validation.md) -> implement
  closed registered typed action dispatch, bounded argument schemas, binding
  and validation error bags, selected/whole/action validation, current
  authorization calls, lifecycle hooks, transaction and after-commit ports,
  and typed render, no-render, redirect, flash, event, and browser-effect
  outcomes.
- Integrate action execution with the iteration-001 snapshot and instance-ledger
  contracts. Tier 0 claim consumption, rollback, duplicate outcome lookup,
  render failure, accepted outcome commit, and refresh-without-replay behavior
  remain explicit; no exactly-once method or external-effect claim is added.
- Actions call host-provided application-service capabilities. The kernel does
  not reproduce Suprnova ORM, policy, session, queue, event, storage, or
  transaction implementations.

### Host boundary, endpoint service, and server security

- [`06-wire-protocol-and-transport.md`](../06-wire-protocol-and-transport.md) ->
  implement a host-neutral v1 endpoint service over the iteration-001 bounded
  parser and typed protocol model. It accepts normalized method/media/version,
  bounded body bytes, endpoint configuration, and a trusted Live request
  context, then returns typed HTTP response intent.
- The endpoint service performs snapshot verification or seed promotion,
  generated registry resolution, model application, declared operation
  dispatch, ledger/transaction coordination, render/dehydrate/sign, response
  encoding, duplicate recovery, and classified failure. Its method, media,
  cache, status, header, size, and compatibility rules are exact and tested.
- [`07-security-and-trust-boundaries.md`](../07-security-and-trust-boundaries.md)
  -> implement the trusted Live request context and hostile-host-adapter
  conformance suite. Kernel entry points reject absent, inconsistent, expired,
  cross-route, cross-principal, or cross-tenant context and reauthorize current
  protected state after verified hydration.
- Host context contains bounded normalized facts and opaque capabilities, never
  raw cookies, CSRF tokens, session secrets, forwarded headers, or reusable
  authorization decisions. Conformance/test builders cannot be enabled in a
  production build accidentally.

### Metadata, checker, harness, fixtures, and budgets

- [`19-developer-tooling-and-testing.md`](../19-developer-tooling-and-testing.md)
  -> add the internal procedural-macro development crate and expansion contract
  required for component, view, field, parameter, action, validation, lifecycle,
  event, effect, and version metadata. Final placement in `suprnova-macros` and
  public path generation wait for the atomic move.
- Implement the Askama-compatible view checker for view existence and source
  structure, component/action/model identities, binding permissions and
  modifiers, stable keys, nested ownership, lifecycle signatures, URL metadata,
  and the server-visible Live directive grammar. Dynamic cases are explicitly
  unproved or use one documented checked escape; they never receive false proof.
- Implement the host-neutral component harness with controlled host context,
  services, sessions, transactions, authorization, time, randomness, ledger,
  parameters, proposals, actions, rendering, and typed outcome assertions.
- Extend the shared fixtures and fuzz/property/concurrency suites for metadata,
  lifecycle, bindings, actions, validation, child parameters, view checking,
  endpoint service, and hostile host adapters. Rust remains the only executor
  for server-only cases; any cross-language protocol case stays in the single
  shared v1 corpus.
- Add a named `A8/16` host-neutral action-framework benchmark that excludes the
  application action body, domain/provider I/O, and Askama render time and
  enforces the architecture's 2-millisecond p95 cap on honestly labelled local
  hardware. Complete environment metadata and at least 30 post-warmup samples
  are mandatory. Validated S1 evidence is first-release qualification.

## Definition of done

Iteration 002 is done only when all of the following are true:

1. The standalone Rust workspace contains cohesive engine and internal
   procedural-macro development packages with exact lockfiles, MSRV, licenses,
   feature declarations, documentation, no production `unsafe`, and no source
   or path dependency on Suprnova or Magnetar.
2. Generated metadata has explicit independent component, view-checker, action,
   state-schema, and protocol version identities. Duplicate names, unsupported
   types, conflicting attributes, invalid signatures, and inaccessible items
   fail through compile-time or deterministic registry diagnostics with useful
   spans/source locations.
3. Askama external templates render through the host-neutral view contract with
   safe default escaping, explicit auditable trusted markup, deterministic
   document/island output, typed response metadata, source-oriented failures,
   and no partial successful output after a render error.
4. Initial component mounting emits one bounded island root, stable
   document-local identity, eligible seed or instanced snapshot, and
   nonexecutable metadata. Multiple and nested mounts preserve ownership and
   reject duplicate identities, key collisions, and circular composition.
5. Lifecycle tests prove the exact initial-mount and action-request phase order,
   allowed mutation/await boundaries, short-circuit behavior, cleanup ownership,
   and failure suppression. No normal request locates a sticky component object.
6. Typed parameters and stable keys distinguish logical children. Signed child
   parameter envelopes reject tampering, wrong parent/child/revision/schema,
   replay from a superseded parent revision, and browser-supplied raw
   substitution; server tests prove update, no-op, remount, removal, and bounded
   non-atomic pending outcomes.
7. Field metadata and runtime checks enforce every state category. Ordinary and
   locked fields reject browser mutation; server-only, session-backed,
   computed, secret, and transient values cannot leak into a new signed
   snapshot or diagnostic surface.
8. Model binding preserves Rust types and distinguishes missing, null, invalid,
   and valid input across supported scalars, options, collections, nested paths,
   enums, date/time values, identifiers, checkboxes, and multi-select controls.
   Unknown, forbidden, conflicting, oversized, or unstable collection paths
   fail before an action observes them.
9. Binding timing and URL declarations have generated/checker/runtime agreement.
   The server produces typed reflected or navigated URL intent and rejects
   sensitive or invalid URL state without claiming browser execution.
10. Only registered actions execute. Typed arguments, action visibility, sync
    and async dispatch, hooks, panics/internal failures, and unknown/malformed
    operation identities have bounded deterministic outcomes.
11. Binding errors and validation errors remain distinguishable and localizable;
    selected, whole-component, action-input, and cross-field validation prevent
    protected effects under policy and implement documented error-bag
    clear/retain/replace behavior.
12. Current authorization is called through trusted host capability after
    verified hydration and before each protected read/effect. Changed principal,
    tenant, resource, route, session, or permission cannot reuse snapshot or
    mount authority and produces no sensitive disclosure.
13. Transaction and ledger tests prove Tier 0 claim consumption, accepted
    outcome commit, rollback/error paths, duplicate recovery, lost response,
    render failure, after-commit ordering, and fresh-render recovery without
    action replay. Tests and docs never claim exactly-once method invocation or
    external effects.
14. Semantic outcomes are closed, bounded, and mutually compatible. Render,
    no-render, safe real-route redirect, flash/session intent, typed events, and
    registered effects encode through protocol v1 with the response-ordering
    guarantees established in iteration 001.
15. The host-neutral endpoint service rejects wrong methods, media types,
    charsets, versions, sizes, cache attempts, missing context, incompatible
    batches, and unsafe redirects before uncertain output is applied. Success,
    duplicate, validation, authn/authz, conflict, refresh, and fatal outcomes
    agree across typed HTTP intent and protocol error/recovery fields.
16. The trusted Live request context cannot be constructed from protocol bytes
    or component state. Host-adapter conformance covers missing, inconsistent,
    expired, cross-origin-attestation, cross-route, cross-principal,
    cross-tenant, rate-limit, and redaction failures while clearly identifying
    the host as the authority responsible for producing truthful attestations.
17. The Askama-aware checker consumes generated metadata and the normative
    template source model. Positive and negative fixtures cover all in-scope
    identities, permissions, modifiers, keys, nesting, URL declarations, and
    dynamic/unproved cases with stable human and machine diagnostics.
18. The component harness can mount, propose values, invoke actions, advance
    lifecycle, inject host failures, and assert HTML, state, errors, events,
    effects, redirects, revisions, snapshots, authorization, transaction order,
    and semantic differences without a browser or actual Suprnova adapter.
19. Unit, macro UI, integration, property, fuzz, and deterministic concurrency
    suites cover success paths and hostile boundaries. Every new external parser
    or verifier has allocation/depth/count bounds, persisted regressions, and no
    hostile-input panic path.
20. The `A8/16` host-neutral action-framework benchmark records honest complete
    environment metadata, at least 30 measured post-warmup samples, and a local
    p95 below 2 milliseconds without timing the application action, domain I/O,
    provider I/O, or Askama rendering. S1 claims continue to fail closed without
    the required environment attestation.
21. Generated expansion size and compile/check work are measured on fixed
    1-, 10-, and 100-component fixtures, grow without unexplained superlinear
    behavior, and retain checked baselines. Release-grade compile-time claims
    require the later validated environment evidence.
22. `scripts/gate.sh` remains unattended, rejects blanket `-D warnings`, and
    includes the structural spec/archive gate, license check, Rust format,
    Clippy review, all feature/target tests, doctests, MSRV, macro UI tests,
    checker fixtures, shared Rust/TypeScript conformance, nightly fuzz build,
    security tests, and both iteration-001 and iteration-002 budget gates.
23. Documentation explains the authoring API, metadata, lifecycle, state,
    bindings, actions, validation, rendering, host adapter contract, trusted
    context, endpoint service, security assumptions, test harness, failures,
    fixtures, and benchmark reproduction without presenting internal
    development paths as final application APIs.
24. The spec source and optional Fable archive match exactly; implementation,
    tests, fixtures, generated artifacts, and docs contain no placeholder,
    unimplemented agreed branch, stale iteration claim, or accidental
    iteration-003-plus behavior.
25. Read-only status inspection and command history confirm the active Suprnova
    and Magnetar worktrees were not modified. The final iteration commit is
    local only and nothing is pushed to origin.
